# Security reporting

Do not post credentials, private data or exploit details in a public issue.
During this repository's private review, use an issue visible only to its
maintainers and authorized collaborators, with synthetic reproduction data.
Never include real credentials, even in a private report.

Before opening the repository to the public, maintainers must enable and verify
GitHub's **Security → Report a vulnerability** route. Once enabled, use that
private route for security reports. Include affected revisions, reproduction,
expected behavior and impact. Do not access other people's data or run destructive
tests. Ordinary bugs without sensitive details can use public issues after launch.

The current source is a developer preview. No fixed response time or security
certification is promised. Maintainers assess reports and publish remediation
information when appropriate.
