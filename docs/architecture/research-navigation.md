# Project research navigation

A Project holds mixed material, investigations and outputs. Overview is a permanent
navigation destination beside the preserved live workspace, not a Project type.
The collapsible Project index links Overview, Studies, Inputs, Results and Activity.
Inputs and Results reuse the shared inventory; Data remains the complete inventory.
Closing a page closes its view, not its evidence.

## Pages and viewer state

Ordinary retained-file navigation reuses an unpinned reader page, matching the exact
Project/document/revision. Open in new Tab, Pin and the existing workspace placement
controls remain explicit. Notes and work arrangements are never replaced by reader
navigation. Reader Back retains earlier exact references within this browser session.
Pins, Overview selection and last-visit checkpoints are additive viewer preferences;
old saved workspace schemas remain readable. Background researchers update their
records without opening a tab unless the person has opened that effort.

Overview uses existing Study/inventory/operation projections. It presents purpose,
dated changes, observed execution, attention items and continuation. First-visit
history is distinct from changes since the previous opening. The checkpoint captured
on opening stays fixed during that visit; Mark seen advances it. These are viewing
preferences, never accepted scientific history. Reports awaiting review remain visible.
A connection is authorization, a claim is assignment ownership, and a running scientific
operation is observed execution. None implies the other. No completion percentage or
automatic summarizing model call is introduced.

## Assignment and plan authority

Collaboration tasks and scientific/provider tasks share the retained Study but have
separate counts. Coordination carries no provider charge. WorkflowService and door
operation receipts remain the only execution authorities. Stopping a Study prevents
future admission; observed stopping of its original workflows remains separate.

Only the local owner reviews a plan or releases assignment ownership. Contributors
may propose a revision but cannot raise owner-established ceilings. Revising a reviewed
plan retains its prior plan and experiment references; it becomes a draft requiring
review. Existing workflow definitions and runs stay frozen. Unrelated Study revisions
do not invalidate a plan edit, but a concurrent change to the plan itself does.

Recovery first reconciles every pending admission against its original actor, request
and operation. Discovered receipts are retained even if release is refused while an
operation is active or uncertain. No reconciliation dispatches replacement work.
Terminal, resolved claims may be released with prior authorship preserved. A cancelled
assignment remains cancelled. Reconciled request keys cannot create a later duplicate.

New assignment proposals retain objective, uncertainty, expected output, dependencies,
evidence, decision impact and why new work is justified. Parent/approach grouping uses
recorded relationships only. An external agent must pick up the saved assignment via
the supported connector; Hooke does not silently launch subscribed agents.

## Compatibility and verification

UI and connector reuse research coordination, Project grants and immutable evidence.
The shared Project-state contract adds coordination counts; it does not introduce
another scheduler or job ledger. Reader preferences have no execution authority.

Focused tests cover exact-reference reuse, Project switching, plan conflicts, owner
review, expiry, stopped assignments and lost-admission receipts. Browser checks,
actual connector continuation, integrated checks and scale fixtures are recorded
separately in the private handoff. Passing fixture tests alone is not usability or
scientific validation. No contest submission or scientific campaign is part of this
navigation milestone.
